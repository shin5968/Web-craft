# 호환성 검증 기록

## 현재 상태

목표: 최신 Java 에디션의 특정 버전을 고정해 브라우저에서 실행 가능성을 검증.
첫 자동 분석에서 26.3과 의존성 목록·파일 해시를 확보했습니다. Java 웹 실행은 아직 미검증입니다.
이 저장소에는 Minecraft 코드나 게임 실행 기능이 없습니다.

| 항목 | 상태 | 다음 통과 기준 |
| --- | --- | --- |
| JAR 정적 분석 | 26.3 및 115개 JAR 분석 완료 | 실행 경로별 의존성 분류 |
| Java 실행 경로 | 미검증 | 필요한 bytecode·표준 API를 웹에서 실행 |
| TeaVM 활용 | 후보, 미검증 | 실제 게임 코드 일부의 컴파일·실행 성공 |
| WebGPU 진단 | 사용자 iPad에서 장치 생성·렌더 패스 완료 보고 | 실제 게임 렌더러 검증은 별도 |
| Wasm GC | 사용자 iPad에서 구조체 생성·읽기 42 성공 보고 | Java 컴파일 결과 실행 검증은 별도 |
| 공유 메모리 | 사용자 환경에서 격리 false·API 미노출 | 격리 구성 후 Worker 원자적 쓰기 결과 42 |
| WebGPU 게임 렌더러 | 미구현 | 게임 데이터에서 청크 하나 표시 |
| 오디오·저장·네트워크 | 미구현 | 각 브라우저 API 경로의 독립 검증 |
| 인증·모드·전체 싱글플레이 | 미구현 | 기본 클라이언트 실행 후 범위 결정 |

## 기록할 환경

- 게임 버전과 JAR SHA-256
- 함께 분석한 의존성 JAR 목록
- Python/분석 도구 버전과 Git commit
- iPad 모델·iPadOS·브라우저 버전, 브라우저 진단 결과
- Java 웹 실행 후보와 정확한 버전, 컴파일 오류와 재현 명령

## 결과 해석

`risk_references`는 조사할 후보 목록입니다. 참조가 있어도 실제 실행 경로에서는 사용하지 않을 수 있으며,
참조가 없어도 동적 로딩·리플렉션·메서드 디스크립터 등에 의존성이 숨어 있을 수 있습니다.
native 메서드가 0개여도 LWJGL 등 별도 의존성의 native 호출이 없어지는 것은 아닙니다.
클래스 버전 분석은 해당 JVM용 파일 형식임을 보여 줄 뿐, TeaVM이나 웹 JVM의 지원 여부를 판정하지 않습니다.
브라우저 WebGPU 성공도 Minecraft 구동 성공을 의미하지 않습니다.

현재 보고서는 OS 규칙 필터 없이 artifact를 수집해 여러 OS용 native JAR도 포함합니다.
첫 target.json의 scope 문자열은 native classifier 제외 범위를 넓게 표현했으나,
실제로는 downloads.artifact의 native JAR도 포함하며 별도 downloads.classifiers 항목만 수집하지 않습니다.

게임의 작고 플랫폼 독립적인 코드 일부에 대해 실제 컴파일·실행을 확인합니다.
Wasm GC 성공만으로 이 관문을 통과할 수는 없습니다.


## Java 컴파일 실행 실험

`java-smoke/`는 독립적으로 작성한 작은 Java 프로그램이며 Minecraft 코드가 아닙니다.
JDK 25의 class format 69를 입력해 TeaVM 0.16.0으로 Wasm GC를 생성합니다.
객체·record·배열·정수 연산·예외 처리를 검증합니다. class format을 읽는 것과
Java 25 전체 언어·라이브러리·동적 로딩 기능을 지원하는 것은 별개입니다.
워크플로 결과와 iPad 실행 결과를 각각 확인해야 합니다.

## 원본 Minecraft 클래스 실험

`minecraft-smoke`는 26.3 client JAR의 `net.minecraft.util.FastBufferedInputStream`을 직접 참조합니다.
클라이언트 SHA-256을 기존 정적 분석 결과로 고정하고, 원본 JAR은 다운로드 후 임시 로컬 경로에 저장합니다.
테스트 wrapper는 원본 버퍼 읽기·건너뛰기·잔여 길이 메서드를 호출하고 JS 참조값과 비교합니다.
검증 범위는 버퍼 읽기 42건·건너뛰기/잔여 길이이며 게임 초기화·월드·렌더링은 포함하지 않습니다.
빌드와 실제 iPad 실행 상태는 각각 별도로 확인합니다.


첫 ARGB 시도에서는 정적 초기화 `ARGB → Util → com.mojang.logging.LogUtils`가
누락된 로깅 의존성을 요구해 TeaVM 빌드가 중단됐습니다.
플랫폼 초기화가 없는 원본 버퍼 스트림 클래스로 첫 실행 검증 범위를 조정했습니다.
이 장애물은 전체 게임 이식 시 공통 유틸리티 초기화를 별도로 검토해야 한다는 증거입니다.


### 원본 클래스 빌드·실행 검증 결과

원본 게임 코드 일부의 웹 컴파일·실행 경로를 확보했지만 전체 게임은 실행하지 않았습니다.
이 원본 클래스 실험의 iPad 실행은 아직 확인하지 않았습니다.


## 청크 비트 저장소 검증

원본 `SimpleBitStorage`, 인터페이스 `BitStorage`, 내부 InitializationException 클래스도
기존 해시 고정 client JAR에서 확인하고 provenance에 클래스별 SHA-256을 기록합니다.
추가 의존성은 게임 메타데이터와 같은 Apache commons-lang3 3.20.0입니다.
합성 정수 인덱스를 24개 비트 폭/크기 조합으로 저장하고,
읽기·교환·복사·압축 데이터 재로딩·일괄 채우기·잘못된 인덱스/값 처리를 검사합니다.
JS BigInt로 독립 계산한 64비트 word와 실제 getRaw의 상·하위 32비트를 비교합니다.
이 단계는 청크 저장 기초 연산이며 실제 PalettedContainer·블록 레지스트리·NBT 월드 로딩은 아닙니다.

## WebGPU 테스트 섹션 렌더러

원본 SimpleBitStorage로 4096개 테스트 팔레트 인덱스를 저장·읽기·검증한 뒤,
직접 작성한 노출 면 메쉬와 WGSL 셰이더로 표시합니다.
16×16×16 합성 섹션이며 실제 Minecraft PalettedContainer·블록 레지스트리·월드는 사용하지 않습니다.
캔버스 드래그 회전과 확대/축소를 지원하고, 깊이 버퍼와 뒷면 제거를 사용합니다.
기존 진단용 캔버스와 별도 GPU 장치·캔버스를 사용합니다.
메쉬 단위 검사, 실제 원본 저장소 연결, headless WebGPU 화면/회전 검증을 추가했습니다.
실제 iPad 렌더링 검증은 아직 수행하지 않았습니다.

## 블록 선택·편집 실험

짧은 탭과 드래그를 구분하고 카메라 광선으로 가장 가까운 블록과 면을 선택합니다.
노란색 선택 표시, 블록 삭제·인접 면 설치·초기화를 제공합니다.
원본 저장소의 set/get으로 수정·검증한 뒤 메쉬와 정점 버퍼를 다시 만듭니다.
저장되지 않는 테스트 섹션이며 실제 Minecraft 블록 레지스트리·물리·게임 규칙은 아닙니다.
광선의 6방향 면·가까운 교차점·빗나감, 원본 저장소 편집, 브라우저 탭/드래그·삭제·설치·초기화를 검사합니다.

iPad의 새 터치 편집 동작은 사용자 실기기에서 추가 확인이 필요합니다.


## iPad에서 보고된 캔버스 컨텍스트 생성 실패

사용자가 업데이트된 편집 페이지에서 `WebGPU canvas를 생성하지 못했습니다` 오류를 보고했습니다.
이는 원본 Java 코드나 셰이더 실행 이전의 getContext('webgpu') null 분기입니다.
스크린샷만으로 Safari의 내부 실패 원인은 확정하지 않았습니다.
렌더러 시작마다 캔버스 요소를 교체하고, 첫 null 시 새 요소로 한 번 재시도합니다.
컨텍스트는 비동기 로딩 및 GPU 장치 생성 전에 확보하며 종료 시 장치를 해제합니다.
이전 캔버스에 2D 모드가 있는 경우, 첫 WebGPU 컨텍스트가 null인 경우,
반복 시작의 새 캔버스 사용을 브라우저 통합 검사에 포함했습니다.
Safari 실기기 복구 여부는 사용자의 추가 확인이 필요합니다.

## 실제 청크 형식 파일 가져오기

이름 있는 Java NBT의 12개 payload 타입, Java modified UTF-8, MCA 섹터 헤더와
압축 방식 1(gzip)·2(zlib)·3(raw)를 직접 작성한 브라우저 파서로 처리합니다.
원본 JAR의 StateHolder 상수에서 id/properties, SerializableChunkData에서 sections/Y/block_states/data 필드를 확인했습니다.
26.3 문자열 상태와 compound 상태, 빈 이름으로 감싼 문자열, 이전 Name/Properties 상태를 처리합니다.
NBT 파서 자체는 Mojang NbtIo를 이식한 것이 아닙니다.

원본 SimpleBitStorage에 NBT의 64비트 long 배열을 직접 전달하는 Java bridge를 추가했습니다.
팔레트 인덱스 4096개를 BigInt 독립 디코더와 비교하고, 0번 상태가 비공기여도 보존합니다.
실제 PalettedContainer·블록 레지스트리·월드 초기화는 여전히 사용하지 않습니다.
한 섹션을 근사 색상/정육면체로 표시하며 원본 블록 이름·속성을 보관합니다.
압축/문자열/경계/잘린 입력, 원본 long 배열 입력, 브라우저 파일 선택→표시 경로를 합성 MCA/NBT로 검사합니다.
실제 26.3 게임에서 저장한 사용자 월드 파일은 아직 제공되지 않아 검증하지 않았습니다.
LZ4, 외부 .mcc, 구형 BlockStates 형식, 투명성·실제 블록 모델·파일 쓰기는 미지원입니다.


### MCA/NBT 통합 검증 결과

[합성 MCA/NBT 통합 검증 성공 기록](https://github.com/shin5968/Web-craft/actions/runs/40453578703)

팔레트 크기 1·2·5·17·33·257·4096 및 혼합 상태 표현의 8가지 경우에서
원본 raw-long 생성자의 4096개 인덱스가 각각 참조 디코더와 일치했습니다.
0번이 비공기인 팔레트, 단일 상태의 data 생략, signed long, 비트 패딩,
잘못된 데이터 길이/인덱스와 가져온 섹션의 편집·초기화 검사가 통과했습니다.
브라우저 파일 선택기에서 합성 .mca를 가져와 원본 저장소로 디코딩하고,
1664개 블록 표시와 원본 snowy 속성 보존·초기화까지 검증했습니다.
실제 게임에서 저장한 26.3 사용자 월드 파일과 iPad의 파일 가져오기는 아직 미검증입니다.


## 사용자 iPad MCA 파일 선택 확인

사용자 스크린샷에서 아이패드 파일 선택기로 `world-fixture.mca`를 고르고,
5개 블록 상태·4096개 인덱스 일치·1664개 블록 표시가 성공한 것을 확인했습니다.
선택한 파일은 합성 fixture이므로 실제 게임에서 저장한 월드 검증과 구분합니다.

## 선택 청크 전체 검사 및 JSON 보고서

실제 월드 파일이 아직 제공되지 않아 호환성 결과를 임의로 확정하지 않습니다.
사용자가 선택한 청크의 각 지원 섹션을 원본 SimpleBitStorage로 검사하고,
일부 실패가 있어도 나머지 결과를 모으도록 했습니다.
브라우저에서 파일 SHA-256(32 MiB 이하), DataVersion·좌표·압축 방식,
섹션별 인덱스 검증/비공기 수/최대 32개 상태 요약·오류를 JSON으로 저장합니다.
읽기 실패 보고서도 제공하며, 전체 파일 데이터나 엔티티 데이터를 포함하지 않습니다.
원본 파일을 수정하거나 보고서를 자동 업로드하지 않습니다.


## 사용자 실제 월드 검사 보고서 확인

사용자가 제공한 r.-1.0.mca 검사 보고서에서 선택 청크 (-32,0), DataVersion 5023,
24개 섹션·98,304개 인덱스 검증 통과, 오류 0개를 확인했습니다.
Y=-4는 물·자갈·기반암, Y=-3~1은 물, Y=2~19는 공기로 보고됐습니다.
보고서는 선택 청크만 검증하며 리전 전체나 파일 출처를 인증하지 않습니다.

## 청크 전체 높이 보기

원본 저장소로 각 섹션을 디코딩한 후 음수 Y를 보존하고 수직으로 합쳐 표시합니다.
섹션별 팔레트를 독립적으로 유지하며 정점 색상으로 합칩니다.
맞닿은 위아래 섹션의 가려진 면을 제거하고 공기 전용 섹션은 메쉬에서 제외합니다.
비공기 블록의 실제 Y 범위에 맞춰 가운데와 카메라 거리/깊이 범위를 설정합니다.
전체 보기는 읽기 전용이며 기존 단일 섹션 편집 보기로 전환할 수 있습니다.
검증은 합성 다중 섹션 MCA로 수행하며 실제 사용자 파일의 전체 높이 표시는 추가 확인이 필요합니다.
