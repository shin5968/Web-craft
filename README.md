# Web-craft

최신 Minecraft Java 에디션의 브라우저 이식 가능성을 검증하는 실험 저장소입니다.
현재는 **JAR 정적 분석 도구, 브라우저 기능 진단 페이지, 작은 Java 프로그램의 Wasm GC 빌드 실험**을 제공합니다.
Minecraft 실행, 완전한 Java 25 웹 런타임, 게임 코드의 TeaVM 변환, 청크 렌더러는 구현하지 않았습니다.

## iPad + Codespaces에서 바로 실행

별도 호스팅이나 artifact 다운로드 없이 Codespaces 안에서 빌드·서빙할 수 있습니다.

1. Codespaces 터미널에서 `git pull --ff-only`로 최신 코드를 가져옵니다.
2. 명령 팔레트에서 **Codespaces: Rebuild Container**를 실행합니다.
   새 설정이 JDK 25·Maven·Node 24·Python을 설치합니다. 완료 후 새 터미널을 여세요.
3. 저장소 루트에서 다음을 실행합니다.

```bash
bash tools/start_codespaces.sh
```

빌드·Java Wasm 실행 검증이 성공하면 개발 서버가 계속 실행됩니다.
**Ports → 8000 → Open in Browser**로 포워딩된 HTTPS 주소를 Safari 새 탭에서 열고,
**환경 검사 시작**, **Java 실행 검사**를 누르세요. 포트는 비공개 상태로 사용할 수 있습니다.
로컬 서버는 HTTP이며 Codespaces의 외부 포워딩 주소가 HTTPS를 제공합니다.

개발 서버는 web 폴더만 제공하며 COOP/COEP와 캐시 비활성 헤더를 보냅니다.
페이지 격리 성공은 프록시와 브라우저를 통과한 실제 `격리 컨텍스트` 값으로 확인하세요.
Codespaces 안의 미리보기 iframe 대신 Safari 새 탭에서 직접 여세요.
서버 종료는 Ctrl+C이며 Codespace가 중지되면 주소도 응답하지 않습니다.
이미 필요한 도구가 설치되어 있다면 컨테이너 재빌드 없이 3번부터 시도할 수 있습니다.
포트 사용 중 오류가 나면 기존 8000 서버를 실행한 터미널에서 종료한 뒤 다시 실행하세요.

## JAR 분석

### iPad에서 GitHub Actions 사용

저장소의 **Actions → Inspect Minecraft target → Run workflow**에서 실행합니다.
분석 도구나 이 워크플로가 main에서 변경될 때도 최신 정식 버전을 자동 분석합니다.
`version`에 공식 버전 ID를 지정하거나 `latest-release`를 사용하세요.
공식 메타데이터가 지정한 클라이언트와 라이브러리 JAR을 임시 다운로드하고 해시를 검증한 뒤 정적 분석합니다.
게임 코드를 실행하지 않으며, 결과물 `compatibility-report`에는 JSON 보고서만 포함합니다.
`target.json`에 실제 선택한 버전, Java 요구 정보, JAR별 SHA-256이 기록됩니다.
모든 라이브러리 artifact JAR을 OS 규칙 필터 없이 분석하므로 artifact로 등록된 native JAR도 포함합니다. 별도 downloads.classifiers 항목과 assets는 제외합니다.
따라서 iPad 실행용 라이브러리 구성이 확정되는 것은 아닙니다.

### 개발 환경에서 직접 실행

Python 3.10 이상, 외부 패키지 없이 실행합니다. 소유한 게임 설치 파일을 로컬에서 분석하세요.
게임과 의존성 JAR을 모두 입력해야 분석 범위가 넓어집니다. 다운로드나 코드 실행은 하지 않습니다.

```bash
python3 tools/inspect_jar.py /path/to/client.jar /path/to/library.jar --output reports/compatibility.json
```

클래스 버전, native 메서드 선언, 위험 API 참조, 동적 로딩 메서드 참조, 포함된 네이티브 파일을 JSON으로 출력합니다.
클래스 major version 69는 Java 25 형식이며, 이것만으로 Java 25 전체 기능 사용 여부를 알 수는 없습니다.
리플렉션으로 구성되는 이름, 실행 중 로딩되는 코드, 모든 디스크립터 참조를 완전히 추적하지 않습니다.
멀티 릴리스 JAR의 버전별 클래스는 별도로 집계합니다. 자세한 한계는 보고서의 `limitations`를 확인하세요.
정상 분석은 종료 코드 0, 파일/클래스 오류가 있으면 부분 보고서를 출력하고 1을 반환합니다.

## 브라우저 진단

주요 대상 기기는 **iPad**입니다. iPad에서는 진단 페이지를 HTTPS로 호스팅한 주소에서 열어 검사합니다.
이 저장소는 아직 호스팅을 구성하지 않았으며, GitHub 파일 보기 화면에서는 페이지가 실행되지 않습니다.
아래 Python 명령은 별도 개발 컴퓨터용이며 iPad Safari에서 실행하는 명령이 아닙니다.

```bash
python3 -m http.server 8000 --directory web
```

같은 기기에서 `http://localhost:8000`을 열고 검사 버튼을 누르세요.
휴대폰에서 다른 컴퓨터의 LAN HTTP 주소로 접속하면 보안 컨텍스트가 아니므로 WebGPU가 노출되지 않을 수 있습니다.
다른 기기에서 접속하거나 배포할 때는 HTTPS를 사용하세요.

WebGPU 어댑터·장치 생성과 단색 렌더 패스 제출을 검사합니다.
Wasm GC는 작은 모듈의 구조체 생성·필드 읽기를 실제 실행합니다.
격리 컨텍스트에서는 Wasm 공유 메모리와 Worker의 Atomics 쓰기·읽기를 검사합니다.
이 검사는 Java 스레드나 실제 Wasm 스레드 프로그램의 실행을 증명하지 않습니다.
WebAssembly, SharedArrayBuffer 노출 여부도 표시하지만 Java·Wasm GC·병렬 실행 호환성을 증명하지는 않습니다.
기본 Python 서버는 COOP/COEP 헤더를 보내지 않으므로 격리 컨텍스트가 false인 것이 예상 결과입니다.
향후 공유 메모리 구성을 사용할 때는 COOP/COEP와 교차 출처 리소스 정책을 함께 설계해야 합니다.

## Java → Wasm GC 실행 실험

Actions의 **Build Java Wasm GC smoke**가 Temurin JDK 25로 원본 테스트 코드를 컴파일한 뒤
클래스 형식 69를 확인하고 TeaVM 0.16.0으로 Wasm GC를 생성합니다.
Node.js에서 객체·배열 체크섬 6건과 예외 처리를 검증한 후 `java-smoke-site` artifact를 제공합니다.

아이패드에서 실행하려면 이 artifact를 압축 해제한 **전체 내용**을 현재 HTTPS 호스팅에 배포하고,
페이지의 **Java 실행 검사** 버튼을 누르세요. 생성 파일은 소스 저장소에 커밋하지 않습니다.
`web` 소스만 배포하면 Java Wasm과 runtime 파일이 없어서 안내 오류가 표시됩니다.
자동 호스팅 배포는 이 워크플로에 포함하지 않습니다.

개발 환경에서는 JDK 25와 Maven으로 다음을 실행합니다.

```bash
mvn -B -f java-smoke/pom.xml package
node tools/check_java_smoke.mjs
```

이 실험은 직접 작성한 작은 Java 코드의 class 69 → Wasm GC 경로를 확인합니다.
Minecraft 클래스·모드·JNI·Java 25 전체 표준 API의 지원을 뜻하지 않습니다.


## Minecraft 원본 클래스 실행 실험

Codespaces에서 서버를 Ctrl+C로 종료하고 `git pull --ff-only` 후
`bash tools/start_codespaces.sh`를 다시 실행하세요. 추가 컨테이너 재빌드는 필요하지 않습니다.
스크립트가 해시로 고정한 26.3 원본 client JAR을 받아 FastBufferedInputStream 메서드를 TeaVM에 입력하고,
Java 테스트와 별도로 `web/minecraft-smoke`에 Wasm GC 모듈을 만듭니다.
페이지의 **Minecraft 원본 클래스 검사**를 누르면 버퍼 읽기 42건·건너뛰기/잔여 길이을 검사합니다.

게임 코드를 복사하거나 해당 메서드를 재구현하지 않고 원본 클래스 바이트코드를 입력합니다.
전체 클라이언트를 실행하는 것이 아니며 도달 가능한 버퍼 입출력 메서드 일부만 컴파일됩니다.
원본 JAR과 생성된 게임 코드 파일은 로컬 ignored 경로에 두며 저장소에 커밋하지 않습니다.
CI도 생성된 게임 Wasm 대신 provenance·검증 결과 JSON만 artifact로 제공합니다.
JAR 해시·클래스 해시·클래스 형식은 `web/minecraft-smoke/provenance.json`에 기록됩니다.


## 청크 비트 저장소 실험

**청크 비트 저장소 검사** 버튼은 원본 `SimpleBitStorage`·`BitStorage`를 실행합니다.
게임 26.3 메타데이터와 같은 commons-lang3 3.20.0을 의존성으로 사용합니다.
8개 비트 폭(1·4·5·8·9·13·16·31)과 3개 크기(1·17·4096)의 24개 조합을 검사합니다.
읽기·쓰기, getAndSet, 독립 복사, raw long 배열 재로딩, fill, 범위 오류 처리를 포함합니다.
JS BigInt 참조 구현으로 원본의 64비트 압축 배열도 직접 비교합니다.
4096개 항목은 청크 섹션 크기의 합성 인덱스이며, 실제 블록 레지스트리·팔레트·월드 로딩은 아닙니다.
기존과 같이 서버 종료 → git pull → `bash tools/start_codespaces.sh`로 빌드하고 실행합니다.


## 원본 저장소 → WebGPU 테스트 지형

서버 종료 후 `git pull --ff-only`와 `bash tools/start_codespaces.sh`를 실행하고,
**테스트 청크 표시**를 누르면 16×16×16 테스트 지형을 그립니다.
드래그로 회전하고 확대/축소 버튼으로 거리를 조절합니다. 컨테이너 재빌드는 필요하지 않습니다.

직접 작성한 지형 생성기가 만든 4096개 인덱스를 원본 SimpleBitStorage에 저장하고,
원본 get으로 읽은 값을 검증해 외부에 노출되는 면만 메쉬로 만듭니다.
깊이 버퍼와 면 방향 검사를 사용하고, 화면 크기에 맞춰 렌더링 해상도를 제한합니다.
데이터·블록 색상·메쉬·렌더러는 실험용이며 실제 게임 청크·텍스처·지형 생성·게임 렌더러는 아닙니다.
프레임은 시작·회전·확대/축소·크기 변경 시 갱신하며 게임 FPS 벤치마크를 제공하지 않습니다.

CI는 메쉬 토폴로지와 면 방향, 원본 Wasm 저장소 왕복을 확인하고,
소프트웨어 GPU를 사용하는 headless Chromium에서 화면 생성·카메라 드래그·별도 진단 캔버스를 검사합니다.
이 자동 검증은 iPad Safari 실기기 검증을 대체하지 않습니다.


## 터치 선택·블록 파괴·설치

**테스트 청크 표시** 후 블록을 짧게 탭하면 노란색으로 선택됩니다.
**선택 블록 파괴**는 해당 블록을 비우고, **선택한 면에 설치**는 선택 면 옆 빈 공간에
드롭다운에서 고른 테스트 블록을 넣습니다. 드래그는 회전으로 처리하며 선택하지 않습니다.
**지형 초기화**는 생성 직후 데이터로 되돌립니다. 변경 내용은 페이지 메모리에만 있고 저장되지 않습니다.
16³ 섹션 밖이나 이미 블록이 있는 위치에는 설치하지 않습니다.

편집은 원본 SimpleBitStorage에 쓰고 4096개 값 전체를 다시 읽어 검증한 뒤,
노출 면 메쉬와 GPU 정점 버퍼를 갱신합니다. 다른 진단이 같은 Wasm 저장소를 사용해도
현재 장면 데이터를 복구한 뒤 편집하므로 장면 변경이 유지됩니다.
블록 선택·입력·게임 규칙·메쉬 갱신은 실험 코드이며 원본 Minecraft 게임플레이 구현은 아닙니다.


## MCA/청크 NBT 파일 읽기

Codespaces에서 서버 종료 후 `git pull --ff-only`와 `bash tools/start_codespaces.sh`로
새 raw-long Java bridge까지 빌드하세요. 컨테이너 재빌드는 필요하지 않습니다.
아이패드 페이지의 **실제 월드 파일에서 섹션 읽기**를 펼치고,
Java 에디션 저장 폴더의 `region/r.*.*.mca`를 파일 선택기로 고릅니다.
청크와 섹션 Y를 선택한 뒤 **선택한 파일 섹션 표시**를 누릅니다.
단일 청크의 이름 있는 루트 .nbt(원시/gzip/zlib)도 읽습니다. level.dat/구조물 NBT는 청크가 아닙니다.

파일은 브라우저에서만 읽으며 업로드하거나 덮어쓰지 않습니다. 파일 크기 제한 128 MiB,
압축 해제 NBT 제한 32 MiB, 깊이 64·태그 200,000개 제한을 적용합니다.
MCA의 gzip(1)·zlib(2)·비압축(3)을 지원하며 LZ4(4), 외부 .mcc, 오래된 BlockStates 형식은 지원하지 않습니다.

NBT·리전 파서는 직접 작성한 코드입니다. 26.3의 문자열 팔레트, id/properties와
이전 Name/Properties 형태, 빈 키로 감싼 문자열을 처리합니다.
NBT long 배열을 원본 SimpleBitStorage 생성자에 전달한 뒤 4096개 인덱스를 독립 BigInt 디코더와 비교합니다.
단일 상태 팔레트의 data 생략과 팔레트 0번이 공기가 아닌 경우를 구분합니다.
렌더링용으로 공기만 0, 다른 상태는 원본 팔레트 인덱스+1로 매핑하고 이름·속성을 보관합니다.
원본 텍스처/모델/조명은 사용하지 않으며, 비공기 블록은 모두 근사 색상의 불투명 정육면체로 표시합니다.
물·식물·반블록·유리도 해당되므로 실제 게임 화면과는 다릅니다.

**지형 초기화**는 마지막으로 불러온 섹션의 최초 상태로 돌아갑니다.
실제 파일에서 불러온 섹션의 메모리 편집도 지원하지만 MCA/NBT 저장·내보내기는 제공하지 않습니다.
**테스트 청크 표시**를 다시 누르면 합성 지형으로 돌아갑니다.
파일이 없으면 Codespaces의 `reports/world-fixture.mca`를 내려받아 가져올 수 있습니다.
이 파일은 테스트가 생성한 **합성 형식 검증 파일**이며 실제 Minecraft에서 저장한 월드가 아닙니다.


## 실제 파일의 호환성 검사 보고서

파일을 고른 뒤 **선택 청크 전체 섹션 검사**로 해당 청크의 지원되는 모든 섹션을 검사합니다.
한 섹션이 실패해도 나머지 섹션을 계속 검사하며 결과를 각각 보관합니다.
**검사 보고서 저장**을 누르면 아이패드에 `web-craft-report.json`을 다운로드합니다.
파일 읽기에 실패해도 오류 보고서를 저장할 수 있습니다. 보고서를 자동 전송하지 않습니다.

보고서에는 파일명·크기·가능한 경우 SHA-256, 브라우저 환경, DataVersion·청크 좌표·압축 방식,
섹션별 팔레트 수·4096개 인덱스 검증·공기/비공기 개수와 최대 32개 비공기 상태 요약·오류가 들어갑니다.
파일 전체 데이터·NBT 엔티티 데이터는 넣지 않습니다. SHA-256은 브라우저 메모리 사용을 제한하려고
32 MiB 이하 파일에서만 계산하며 더 큰 파일은 생략 사유를 기록합니다.
이 보고서는 선택한 파일의 출처를 인증하거나 전체 게임 호환성을 보증하지 않습니다.

이번 기능은 웹 코드 변경이므로 기존 빌드가 있다면 `git pull --ff-only` 후 Safari를 새로고침하면 됩니다.
실제 게임이 저장한 .mca가 없으면 제공된 합성 파일만으로 실제 월드 호환성을 판정할 수 없습니다.


## 선택 청크의 전체 높이 표시

MCA에서 청크를 고른 뒤 **선택 청크 전체 높이 표시**를 누르면 지원되는 모든 섹션을
원본 저장소로 디코딩하고 수직으로 합쳐 표시합니다. 공기만 있는 섹션은 메쉬에서 생략하며,
위아래 섹션이 맞닿는 가려진 면을 제거합니다. 비공기 블록 범위에 맞춰 카메라 거리와 깊이 범위를 조절합니다.
가로로 이웃한 청크나 리전 전체를 표시하는 기능은 아닙니다.

전체 높이 보기는 **읽기 전용**입니다. 회전·확대/축소를 사용할 수 있고,
섹션을 골라 **선택한 파일 섹션 표시**를 누르면 편집 모드로 돌아옵니다.
물 등은 여전히 불투명 정육면체이므로 내부 구조가 가려질 수 있습니다.
최대 64개 섹션·24 MiB 정점 데이터 제한을 적용하며 복잡한 청크는 섹션별로 확인하세요.
보고서에도 표시 높이 범위·섹션 수·전체 검증 인덱스 수를 기록합니다.
웹 코드 변경이므로 기존 빌드가 있으면 git pull 후 Safari를 새로고침하면 됩니다.
